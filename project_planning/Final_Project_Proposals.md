## Literature Context (Summary)

The 2024-2025 literature reveals that hate speech detection has shifted from "higher F1 on a single dataset" to a robustness frontier. The key findings underpinning our proposals:

1. **Text detection is mature, but brittle.** Fine-tuned encoders (RoBERTa, DeBERTa, XLM-R) perform strongly in-domain but fail under dataset shift, policy mismatch, and implicit hate. LLMs are useful as teachers/rationale-generators but are unreliable as drop-in classifiers (over-sensitive to group mentions, poorly calibrated, inconsistent across models) [ACL 2025, WOAH 2025].

2. **Multimodal detection is the active frontier.** MemeCLIP (2024), MM-HSD (ACM MM 2025), TANDEM (2025), and ImpliHateVid (ACL 2025) push beyond text to memes and video. However, cross-modal reasoning for implicit hate (where image and text are individually benign but hateful together) remains the core unsolved challenge [CVPR 2025 Workshop].

3. **Sarcasm-hate interaction is the #1 cited failure mode.** SarcNet (2024) and multimodal sarcasm work show that a large share of detection errors come from irony, sarcasm, and satire, not overt slurs. No dedicated system jointly models sarcasm and hate [Codex, Claude].

4. **Bias in multimodal classifiers is unstudied.** Bias research is extensive for text (AAE speakers, group mentions) but entirely absent for meme/video hate detectors. A system flagging images of Black people at higher rates would be deeply harmful [Claude, WOAH 2025 taxonomy].

5. **Definition mismatch is a first-order scientific problem.** Different datasets operationalize "hate speech" differently. Model-Dependent Moderation (ACL 2025) shows moderation outcomes depend on which model and which definition is used. No system conditions on explicit policy definitions [Codex].

6. **Video hate detection is early-stage.** HateClipSeg (2025) reveals that in hateful videos, only ~67% of content is actually hateful -- video-level labels are lossy. Temporal localization with modality attribution is nascent [HateClipSeg 2025, MM-HSD 2025].

**Key references for full literature review:** See `Literature_Review_and_Project_Ideas.md` in this directory (50+ papers, 9 research areas covered).

## Proposal 1: Sarcasm-Aware Multimodal Hate Speech Detection

### Why This Project

The course objective explicitly asks for models that "differentiate between harmful hate speech and legitimate critical discourse or satire." This is exactly the problem: current hate detectors systematically confuse sarcastic/satirical content with genuine hate, and miss genuinely hateful sarcasm. This was independently ranked #1 by Codex and #2 by Claude as the strongest project idea.

### Problem Statement

Hate speech detectors suffer from two symmetric failure modes with sarcasm: (1) benign sarcasm mentioning protected groups is flagged as hateful (false positive), and (2) genuinely hateful sarcasm with a surface-positive tone passes undetected (false negative). These failures are amplified in multimodal content (memes, video) where visual context may contradict textual tone. No existing system jointly models sarcasm detection and hate detection in a multimodal architecture.

### Key Innovation / Gap Filled

- **Gap:** Sarcasm-hate interaction is universally cited as a hard problem (SarcNet 2024, MUStARD++ 2022), but no dedicated multi-task solution exists that handles multimodal content.
- **Innovation:** A multi-task disentanglement architecture that learns separate but interacting representations for sarcasm, sentiment, and hate, preventing the hate classifier from being confused by sarcasm signals. Uses gradient reversal to force the hate head to be sarcasm-invariant when sarcasm is benign, while amplifying sarcasm signal when it carries hateful intent.

### Proposed Approach

**Architecture:**
```
Input (Image + Text / Video)
    |
[Shared Multimodal Encoder]  -- CLIP for image+text; or VideoMAE + Whisper for video
    |
[Shared Representation Layer]
    |
    +---> [Sarcasm Head] -- auxiliary task: sarcasm detection
    |         |
    |    [Gradient Reversal Layer] (conditional: active only for non-hateful sarcasm)
    |         |
    +---> [Hate Speech Head] -- main task: hate classification + target prediction
    |
    +---> [Sentiment Head] -- auxiliary task: surface sentiment
```

**Training strategy:**
1. Pre-train the shared encoder on a combined multimodal dataset (Hateful Memes + MultiOFF + MAMI).
2. Multi-task fine-tuning with three heads. Use task-weighted losses with dynamic weight adjustment.
3. Hard negative mining: explicitly construct batches where sarcastic-but-benign and hateful-sarcasm examples are paired, forcing the model to learn the distinction.
4. Contrastive loss between hateful memes and sarcastic-but-benign memes targeting the same groups.

**Key insight the model must learn:** "sarcastic + targets protected group with stereotyping intent = hateful sarcasm" vs. "sarcastic + targets self/general/absurd = benign sarcasm."

### Datasets

| Dataset | Role | Modality |
|---------|------|----------|
| Hateful Memes (Facebook) | Primary hate meme training | Image + Text |
| MUStARD / MUStARD++ | Multimodal sarcasm supervision | Video + Audio + Text |
| iSarcasm | Text sarcasm (with author explanations) | Text |
| News Headlines Sarcasm | Additional sarcasm examples | Text |
| HatEval | Hate speech with target labels | Text |
| MultiOFF | Offensive memes | Image + Text |
| MAMI | Misogynistic memes | Image + Text |
| ETHOS | Multi-label hate (for target types) | Text |
| HarMeme | Harmful memes with targets | Image + Text |

### Why It Could Be Published

- Directly addresses a failure mode cited in dozens of papers but with no dedicated solution.
- Novel multi-task architecture with gradient reversal for sarcasm-hate disentanglement.
- Strong qualitative results potential (side-by-side comparisons of sarcasm misclassification).
- Clear evaluation: measure false positive rate on sarcastic-benign content and false negative rate on hateful-sarcasm content.
- Target venues: EMNLP, ACL, WOAH workshop, or EACL.

### High-Level Implementation Plan

| Week | Milestone |
|------|-----------|
| 1 | Dataset acquisition, preprocessing, and unified label mapping. Build sarcasm/hate label taxonomy. |
| 2 | Implement shared CLIP-based multimodal encoder with multi-task heads. Baseline training (hate-only). |
| 3 | Add sarcasm and sentiment auxiliary heads. Implement gradient reversal layer. |
| 4 | Hard negative mining pipeline. Contrastive loss implementation. |
| 5-6 | Ablation studies: measure contribution of each component (sarcasm head, gradient reversal, contrastive loss). |
| 7 | Cross-dataset evaluation. Qualitative error analysis. Fairness metrics. |
| 8 | Paper writing, poster preparation. |

### Potential Challenges

- **Domain gap** between sarcasm datasets (TV shows in MUStARD) and hate datasets (social media). Mitigation: domain-adaptive fine-tuning, focusing on shared sarcasm features.
- **Label schema differences** across datasets. Mitigation: careful ontology design before training.
- **Annotation subjectivity** for sarcastic hate is inherently high. Mitigation: report inter-annotator agreement; flag uncertainty.
- **Balancing task losses** in multi-task training. Mitigation: dynamic task weighting (uncertainty-weighted losses).

### Resources Needed

- GPU cluster: 2-4 GPUs for CLIP fine-tuning (~2-3 days training per run)
- All datasets are publicly available (Hateful Memes requires DrivenData registration)
- Pre-trained models: CLIP (OpenAI), MUStARD++ video features

## Proposal 2: Fairness-Aware Multimodal Hate Speech Detection with Bias Auditing

### Why This Project

Bias in text-based hate speech classifiers is well-documented: they disproportionately flag African-American English and content mentioning protected groups. But **no one has studied whether multimodal hate classifiers (for memes, videos) exhibit similar or even worse biases**. A meme classifier that flags images of Black people at higher rates than comparable images of White people would be deeply harmful -- and this has never been tested. This was ranked #1 by Claude and aligns with Codex's #4 (causal debiasing).

### Problem Statement

Multimodal hate speech classifiers process both text and images, meaning they can inherit biases from both modalities. Visual biases (skin color, religious symbols, gender presentation in images) may compound text biases in ways that text-only bias research cannot predict. Despite extensive work on text bias (WOAH 2025 taxonomy, FairPrism), **no systematic bias audit exists for multimodal hate detectors**, and no debiasing method operates across modalities.

### Key Innovation / Gap Filled

- **Gap:** Bias in multimodal hate classifiers is entirely unstudied (confirmed by Claude's literature review across 50+ papers).
- **Innovation:** (1) First systematic bias audit of SOTA multimodal hate detectors using counterfactual meme generation, (2) An adversarial debiasing method that operates at the multimodal fusion layer, and (3) An intersectional fairness evaluation framework for multimodal content.

### Proposed Approach

**Phase 1: Bias Audit**
1. Select 3-4 SOTA multimodal hate detectors (MemeCLIP, Pro-Cap, CLIP+classifier, a fine-tuned LMM).
2. Create a **Counterfactual Meme Test Set**: take memes from Hateful Memes / MMHS150K, and systematically swap identity-related visual elements (skin color, religious symbols, gender) while keeping text constant. Use controlled image editing (inpainting) or template-based generation.
3. Measure: equalized odds, demographic parity, false positive rate disparity, and prediction flip rate across identity swaps.

**Phase 2: Debiasing**
```
Input (Image + Text)
    |
[CLIP Image Encoder]  [CLIP Text Encoder]
    |                       |
    +-------[Fusion Layer]-------+
                |
        [Adversarial Debiasing Head]  -- predicts protected attribute; gradient reversed
                |
        [Hate Classification Head]  -- main task
                |
        [Fairness-Constrained Loss] = L_hate + lambda * L_adversarial + mu * L_fairness
```

4. The adversarial head forces the fusion representation to be invariant to protected attributes.
5. The fairness-constrained loss penalizes equalized odds violations during training.
6. Compare debiased model accuracy vs. fairness tradeoff.

**Phase 3: Intersectional Analysis**
- Evaluate bias at the intersection of multiple attributes (e.g., Black + female, Muslim + male).
- Report whether debiasing for one attribute inadvertently increases bias for another.

### Datasets

| Dataset | Role |
|---------|------|
| Hateful Memes (Facebook) | Primary multimodal hate dataset |
| MMHS150K | Large-scale multimodal hate speech |
| FairPrism | Fairness evaluation framework and annotations |
| Racial Stereotypes Dataset | Racial bias testing |
| MAMI | Gender-based bias testing (misogyny) |
| Counterfactual test set | Created by the project (core contribution) |

### Why It Could Be Published

- **First-of-its-kind contribution**: no prior work audits bias in multimodal hate detectors.
- The counterfactual meme test set is itself a reusable contribution.
- Strong alignment with FAccT, AIES, and WOAH venues.
- Directly serves the "ML for good" mission -- preventing classifiers from becoming tools of discrimination.
- Timely: as multimodal classifiers get deployed, understanding their biases is critical.

### High-Level Implementation Plan

| Week | Milestone |
|------|-----------|
| 1 | Reproduce 3-4 SOTA multimodal hate detectors. Acquire and preprocess datasets. |
| 2 | Design and generate counterfactual meme test set (identity swaps via inpainting/templates). |
| 3 | Run bias audit on all models. Compute fairness metrics. Analyze results. |
| 4 | Implement adversarial debiasing at fusion layer. Train debiased model. |
| 5 | Fairness-constrained loss experiments. Accuracy-fairness tradeoff curves. |
| 6 | Intersectional analysis. Cross-dataset evaluation. |
| 7 | Ablations, qualitative analysis of bias cases, comparison before/after debiasing. |
| 8 | Paper writing, poster preparation. |

### Potential Challenges

- **Counterfactual meme generation quality**: identity swaps must be realistic to avoid artifacts. Mitigation: use template-based memes and high-quality inpainting; manually verify a subset.
- **Defining protected attributes in images**: visual identity is complex and not always inferable. Mitigation: use clear, unambiguous visual cues; document limitations.
- **Disentangling legitimate context from bias**: some images genuinely correlate with hate content. Mitigation: use counterfactual pairs where context is controlled.
- **Small test set size**: generating high-quality counterfactuals is slow. Mitigation: start with 200-500 counterfactual pairs; quality over quantity.

### Resources Needed

- GPU cluster: 2-4 GPUs for reproducing SOTA models and training debiased variants
- Image editing tools: stable diffusion inpainting or manual template editing
- All datasets publicly available (some require registration)

## Proposal 3: Commonsense-Augmented Implicit Hate Detection in Memes

### Why This Project

Hateful memes represent one of the hardest challenges in content moderation because they exploit **compositional meaning**: the image and text are individually benign but hateful in combination. Understanding this requires world knowledge (who is in the image, what stereotypes exist, what the text implies in context). This idea converged across all three agents (Claude #3, Gemini #3, Codex #4) and extends the hottest current direction (CVPR 2025 Workshop on LMM-generated knowledge for memes).

### Problem Statement

Current meme classifiers using CLIP-based fusion achieve strong results on explicit hate but fail dramatically on implicit/compositional cases. For example, a photo of a historical figure paired with an apparently neutral quote can be deeply hateful if the viewer knows the context. Standard vision-language models lack the commonsense and world knowledge to decode these implicit references. The Facebook Hateful Memes Challenge (2020) was specifically designed to test this, and it remains far from solved.

### Key Innovation / Gap Filled

- **Gap:** Cross-modal reasoning for implicit hate in memes requires commonsense integration. A CVPR 2025 workshop paper shows LMM-generated knowledge helps, but structured commonsense graph integration is unexplored.
- **Innovation:** A knowledge-augmented pipeline that injects external commonsense (from knowledge graphs and/or LLM-generated inferences) into the cross-modal reasoning process, enabling the model to decode implicit references that pure vision-language models miss.

### Proposed Approach

**Architecture:**
```
Input Meme (Image + Text)
    |
[CLIP Image Encoder]    [CLIP Text Encoder]
    |                        |
    +---[Entity/Concept Extraction]---+
                |
    [Commonsense Retrieval Module]
        |-- ConceptNet triples (structured)
        |-- LLM-generated inferences (e.g., "This image shows [person X];
        |   the text implies [stereotype Y] about [group Z]")
                |
    [Cross-Attention Fusion]
        |-- CLIP embeddings (visual + textual)
        |-- Commonsense embeddings (structured + free-text)
                |
    [Classification Head] --> hateful / not-hateful / target group
```

**Training strategy:**
1. Freeze CLIP encoders (proven effective for memes).
2. Train the commonsense retrieval module: for each meme, generate 3-5 commonsense inferences using an LLM (Llama-3-8B), encode them, and learn to attend to the most relevant ones.
3. Train the cross-attention fusion and classification head on Hateful Memes + HarMeme.
4. Key experiment: compare performance on "unimodally benign, multimodally hateful" confounders (a specific split in the Hateful Memes dataset) with and without commonsense augmentation.

**Optional extension (from Gemini):** Add a graph neural network (GNN) component that maps entities detected in the image to text tokens and reasons about their relationships via a learned graph.

### Datasets

| Dataset | Role |
|---------|------|
| Hateful Memes (Facebook) | Primary benchmark (designed for compositional confounders) |
| HarMeme | Additional meme hate data with target labels |
| MMHS150K | Large-scale multimodal hate speech |
| Hatemoji | Emoji-based hate (additional challenge) |
| MultiOFF | Offensive memes |
| ConceptNet | Structured commonsense knowledge graph |
| LLM-generated inferences | Free-text commonsense (generated as part of pipeline) |

### Why It Could Be Published

- Extends the CVPR 2025 direction (LMM-knowledge for memes) with a more structured approach.
- The Hateful Memes Challenge is a high-profile benchmark; improvements are always publishable.
- Commonsense reasoning for hate speech is at the intersection of two hot areas (knowledge-grounded NLP + multimodal safety).
- Clear ablation story: with/without commonsense, structured vs. free-text, effect on confounder subsets.
- Target venues: ACL, EMNLP, CVPR workshops, AAAI.

### High-Level Implementation Plan

| Week | Milestone |
|------|-----------|
| 1 | Dataset setup. CLIP baseline on Hateful Memes. Identify confounder subset. |
| 2 | Build commonsense retrieval module: ConceptNet API + LLM inference generation pipeline. |
| 3 | Implement cross-attention fusion between CLIP embeddings and commonsense embeddings. |
| 4 | Train and evaluate on full Hateful Memes. Analyze confounder subset performance. |
| 5 | Optional GNN extension for entity-text relational reasoning. |
| 6 | Ablation studies: commonsense sources, number of inferences, structured vs. free-text. |
| 7 | Cross-dataset evaluation (HarMeme, MMHS150K). Qualitative error analysis. |
| 8 | Paper writing, poster preparation. |

### Potential Challenges

- **Commonsense retrieval noise**: irrelevant or incorrect triples/inferences can hurt performance. Mitigation: confidence filtering; learn to attend selectively.
- **LLM inference cost**: generating commonsense for all training memes. Mitigation: pre-compute and cache; use efficient LLM (Llama-3-8B).
- **Cultural specificity**: meme humor and references are culturally situated. Mitigation: document limitations; focus on English-language memes.
- **Annotation subjectivity**: what counts as "implicit hate" is debated. Mitigation: use the Hateful Memes annotations as ground truth; report disagreement analysis.

### Resources Needed

- GPU cluster: 2 GPUs for CLIP fine-tuning, 1 GPU for LLM inference generation
- Hateful Memes requires DrivenData registration
- ConceptNet is open-access; LLM (Llama-3-8B) available on cluster

## Proposal 4: Temporal and Explainable Hateful Video Detection

### Why This Project

Video is the fastest-growing content format online, but hateful video detection is still in its infancy compared to text and memes. Recent work (HateClipSeg 2025) reveals that in hateful videos, only ~67% of content is actually hateful -- the rest is benign. Video-level labels are therefore lossy and unhelpful for moderators. This idea appeared across all three agents (Claude idea 1, Codex #3, Gemini #6) and represents the most technically ambitious proposal.

### Problem Statement

Current video hate detectors produce a single label for an entire video, but moderators need to know **when** the hateful content occurs, **which modality** carries the hate signal (spoken words? visual symbols? tone of voice? the combination?), and **why** it is hateful. No existing system provides temporal localization with multimodal modality attribution and natural language explanations simultaneously.

### Key Innovation / Gap Filled

- **Gap:** Despite HateClipSeg (2025) providing segment-level annotations, most methods still operate at video-level. Fine-grained temporal grounding with explainable modality attribution is nascent (Claude, Codex, Gemini all identified this).
- **Innovation:** A multi-stream architecture that (1) localizes hateful segments temporally, (2) attributes hate signals to specific modalities at each timestamp, and (3) generates natural language explanations for detected segments.

### Proposed Approach

**Architecture:**
```
Input Video
    |
    +---> [Visual Stream: CLIP/VideoMAE] -- frame-level features
    |
    +---> [Audio Stream: Whisper (ASR) + HuBERT (prosody)] -- transcript + emotion
    |
    +---> [Text Stream: OCR + text encoder] -- on-screen text
    |
[Temporal Cross-Modal Attention Transformer]
    |-- Self-attention within each modality stream
    |-- Cross-attention across modalities at each time step
    |
[Segment Proposal Network] (inspired by temporal action localization)
    |-- Proposes candidate hateful segments with start/end times
    |
[Per-Segment Classification + Modality Attribution]
    |-- Hate/not-hate per segment
    |-- Modality contribution scores (which stream triggered detection)
    |-- Target group prediction
    |
[Explanation Generator] (optional: LLM-based rationale for top segments)
```

**Training strategy:**
1. Pre-train modality encoders on their respective domains (CLIP, Whisper, HuBERT -- all pre-trained).
2. Train temporal cross-modal attention on HateMM with video-level labels (weak supervision).
3. Fine-tune segment proposal network on HateClipSeg segment-level annotations.
4. Multi-instance learning: treat video-level labels as bag labels, segments as instances.
5. Modality attribution via attention decomposition: per-segment attention scores broken down by stream.

### Datasets

| Dataset | Role |
|---------|------|
| HateMM | Primary video hate dataset (CC BY 4.0) |
| MultiHateClip | Multilingual video hate (YouTube + Bilibili) |
| HateClipSeg | Segment-level annotations (5 offensive categories) |
| HateComments | Video comments with target types |

### Why It Could Be Published

- Video hate detection is far less saturated than text/meme work -- higher novelty ceiling.
- Temporal localization + modality attribution is a genuinely new capability.
- Practical value: moderators need exactly this kind of tool.
- Technically deep: multi-stream temporal attention, segment proposals, multi-instance learning.
- Target venues: ACM Multimedia, EMNLP, CVPR (video understanding workshops).

### High-Level Implementation Plan

| Week | Milestone |
|------|-----------|
| 1 | Download and preprocess HateMM + MultiHateClip. Extract frames, audio, transcripts. |
| 2 | Implement individual stream encoders. Baseline: late fusion with video-level labels. |
| 3 | Implement temporal cross-modal attention transformer. |
| 4 | Segment proposal network. Multi-instance learning setup. |
| 5 | Train on HateClipSeg segment-level annotations. Evaluate temporal IoU. |
| 6 | Modality attribution analysis. Per-stream ablations. |
| 7 | Optional: LLM-based explanation generation for detected segments. Cross-dataset eval. |
| 8 | Paper writing, poster preparation. |

### Potential Challenges

- **Compute intensity**: video processing is expensive. Mitigation: sample frames (1-2 fps), use pre-extracted features where possible, limit video length.
- **Small dataset size**: HateMM has ~1,083 videos. Mitigation: data augmentation (temporal crops, speed perturbation); use MultiHateClip for additional data.
- **Annotation alignment**: HateClipSeg segment annotations may not perfectly align with modality-specific hate cues. Mitigation: use segment labels as weak supervision; allow model to refine boundaries.
- **Evaluation of explanations**: requires human study. Mitigation: small-scale human evaluation (50-100 examples) + automated proxy metrics.

### Resources Needed

- GPU cluster: 4+ GPUs recommended for video model training (most compute-intensive proposal)
- Storage: video datasets require significant disk space (~50-100GB)
- Pre-trained models: CLIP, Whisper, HuBERT, VideoMAE (all publicly available)

## Proposal 5: Definition-Conditioned Hate Speech Detection with Calibrated Abstention

### Why This Project

This was Codex's #2 ranked idea and arguably the most **scientifically important** proposal in this list. It addresses what the 2025 literature identifies as the most fundamental structural problem in hate speech detection: different datasets, platforms, and jurisdictions define "hate speech" differently, and models trained on one definition fail on another. Rather than treating this as noise, this project makes the definition itself a first-class input to the model.

### Problem Statement

"Hate speech" means different things in OLID (offensive language), HateXplain (explicit rationales), ETHOS (multi-label), Civil Comments (toxicity), HatEval (anti-immigrant/women), and Davidson (hate vs. offensive). A single binary classifier collapses these incompatible labeling regimes, leading to inconsistent moderation. Model-Dependent Moderation (ACL 2025) shows that outcomes depend strongly on which model is used, especially for specific demographic groups. Meanwhile, hate speech is high-stakes -- a system should often say "uncertain, send to human review" rather than force a binary decision.

### Key Innovation / Gap Filled

- **Gap 1:** Definition mismatch across datasets is identified as a core scientific problem (MetaHate 2024, Web(er) of Hate WOAH 2025) but no model conditions on explicit definitions.
- **Gap 2:** Calibrated abstention (knowing when to say "I don't know") is critical for deployment but absent from hate speech systems.
- **Innovation:** A model that takes both the input text and an explicit policy/definition embedding, predicting whether the input is hateful *under that specific definition*, with uncertainty-aware abstention for borderline cases using conformal prediction.

### Proposed Approach

**Architecture:**
```
Input Text: "You people are all the same"
    |
[Text Encoder: DeBERTa-v3 or XLM-R]
    |
    +---> [Text Representation]
    |
Policy Definition: "Hate speech targets a protected group with intent to
                     dehumanize, threaten, or incite violence" (e.g., UN definition)
    |
[Definition Encoder: same backbone, shared or separate]
    |
    +---> [Definition Representation]
    |
[Cross-Attention: text attends to definition tokens]
    |
[Classification Head] --> P(hateful | text, definition)
    |
[Conformal Prediction / Evidential DL Layer]
    |
    +---> "hateful" (high confidence)
    +---> "not hateful" (high confidence)
    +---> "ABSTAIN -- send to human review" (high uncertainty)
```

**Training strategy:**
1. **Multi-dataset training**: Train on MetaHate + OLID + Davidson + Civil Comments + HateXplain + ETHOS + HatEval + Implicit Hate simultaneously.
2. For each dataset, encode its labeling guidelines/definition as the "policy" input.
3. The model learns: "Under OLID's definition, this is offensive; under HatEval's definition, this targets women."
4. **Abstention via conformal prediction**: calibrate the model so that when it produces prediction sets of size > 1 at a given confidence level (e.g., 95%), it abstains and flags for human review.
5. **Evaluation**: (a) in-distribution: per-dataset accuracy, (b) cross-definition transfer: train on definitions A,B,C, test on unseen definition D, (c) abstention quality: are abstained examples genuinely hard/ambiguous?

### Datasets

| Dataset | Role | Definition Type |
|---------|------|-----------------|
| MetaHate | Unified multi-dataset resource | Multiple definitions |
| OLID | Offensive language identification | 3-level hierarchy |
| Davidson | Hate vs. offensive vs. neither | Crowdsourced definitions |
| Civil Comments | Toxicity ratings | Toxicity scale |
| HateXplain | Explainable hate with rationales | Binary + rationales |
| ETHOS | Multi-label hate speech | 8 label dimensions |
| HatEval | Anti-immigrant / anti-women | Target-specific |
| Implicit Hate | Latent hatred | Implicit vs. explicit |
| MLMA | Multilingual multi-aspect | Aspect-level labels |

### Why It Could Be Published

- Targets the most fundamental problem identified in the 2025 literature.
- Novel framing: definition as a first-class model input (inspired by natural language inference).
- Conformal prediction for hate speech abstention is entirely new.
- Practical deployment value: platforms can plug in their own moderation policies without retraining.
- "Policy-conditioned" models are a growing direction in NLP (instruction-following, RLHF) -- applying this to content moderation is timely.
- Target venues: ACL, NAACL, EMNLP, FAccT.

### High-Level Implementation Plan

| Week | Milestone |
|------|-----------|
| 1 | Acquire all datasets. Design unified data loader. Write textual definitions for each dataset's labeling policy. |
| 2 | Implement baseline: single DeBERTa-v3 multi-dataset classifier (no definition conditioning). |
| 3 | Add definition encoder and cross-attention. Train definition-conditioned model. |
| 4 | Implement conformal prediction calibration. Determine optimal abstention thresholds. |
| 5 | Evaluate: per-dataset accuracy, cross-definition transfer, abstention quality. |
| 6 | Ablations: definition encoder architecture, number of training datasets, abstention threshold sensitivity. |
| 7 | Qualitative analysis: what does the model abstain on? Are these genuinely ambiguous cases? Fairness analysis. |
| 8 | Paper writing, poster preparation. |

### Potential Challenges

- **Label harmonization**: mapping different datasets' label schemas to a unified format is hard. Mitigation: keep labels dataset-specific; the definition embedding handles alignment.
- **Definition quality**: writing precise textual definitions for each dataset is subjective. Mitigation: use the original annotation guidelines as definitions; test sensitivity to paraphrasing.
- **Training instability**: multi-dataset training with different label distributions. Mitigation: balanced sampling; dataset-weighted losses.
- **Conformal prediction calibration**: requires a held-out calibration set per definition. Mitigation: use 10-15% of each dataset for calibration.

### Resources Needed

## Appendix: Additional Ideas Considered but Not Selected

The following strong ideas were generated by individual agents but not selected for the top 5, either due to lower cross-agent convergence or higher risk. They remain viable alternatives:

- **Controllable Counter-Narrative Generation** (Gemini #1): Fine-tune T5/BART to generate counter-narratives conditioned on desired style (formal, humorous, empathetic). High impact but evaluation is very difficult.
- **Detecting AI-Generated Implicit Hate** (Gemini #2): Train a detector for LLM-generated subtle hate speech. Extremely timely but dataset creation is the bulk of the work.
- **Continual Learning for Evolving Hate Speech** (Claude #4, Gemini #5): EWC/progressive networks for adapting to new slang and dog whistles. High novelty but constructing temporal evaluation splits is complex.
- **Annotator Disagreement Modeling** (Claude #5): Predict the full annotation distribution rather than majority vote. Elegant but niche.
- **Knowledge-Grounded Counter-Meme Generation** (Claude idea 6): Generate visual+textual counter-narratives. First-of-its-kind but very risky (generating images that are safe and effective is hard).
- **Cross-Domain Transfer: Social Media to Gaming** (Claude idea 9): Domain-adversarial networks for hate speech transfer from Twitter to gaming. Timely but gaming datasets are very small.
- **LLM Distillation for Efficient Hate Speech Detection** (Claude idea 8): Transfer LLM reasoning into small deployable models. Useful but knowledge distillation is well-studied.
- **Multilingual Shared-Taxonomy Detection with Language-Specific Adapters** (Codex #5): LoRA adapters per language with shared hate taxonomy. Good balance but less novel.
